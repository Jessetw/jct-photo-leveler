# 照片水平調整（Photo Leveler） v1.33.1

單一功能的小工具：把一張照片轉正，旋轉後依**原始長寬比**裁切，輸出高品質 JPEG。

---

## 安裝與啟動

**雙擊 `run.bat`。**

第一次執行會自動建立 `.venv` 並安裝 Pillow / numpy / opencv-python（需要網路，約 1~2 分鐘），
之後再執行就是直接開啟。

前提：電腦已安裝 Python 3.10 以上，且安裝時有勾選「Add python.exe to PATH」。
沒有的話到 <https://www.python.org/downloads/> 安裝即可。

也可以把照片直接拖到 `run.bat` 圖示上，開啟時就會載入那張照片。

### 想要獨立執行檔（不需要 Python）

先跑過一次 `run.bat`，再雙擊 `build_exe.bat`，完成後執行檔在 `dist\照片水平調整.exe`。

`build_exe.bat` 會先做**逐項匯入健檢**（numpy → numpy.random → cv2 → 全部一起），
因為 PyInstaller 打包失敗時的訊息（`Isolated subprocess crashed while importing
package 'numpy.random'`）其實是套件層級的 DLL 衝突，健檢會直接指出是哪一步掛掉、
以及該裝哪一版。

實際建置會在 `%TEMP%\photo_leveler_build` 進行——**刻意避開含中文的路徑**，
PyInstaller 的隔離子行程在非 ASCII 路徑下容易無聲閃退。打包完成才把 exe 複製回
`dist\照片水平調整.exe`。第一次失敗會自動用更精簡的分析範圍再試一次。

| 鍵 | 作用 | 對應按鈕 |
|---|---|---|
| `Z` | 逆時針 **+1°** | 最左 |
| `X` | 逆時針 **+0.1°** | 左內 |
| `C` | 順時針 **−0.1°** | 右內 |

### 選項

- **顯示格線** — 三分法格線 + 中央水平線，方便對齊。
- **只看裁切結果** — 切換成「所見即所得」，直接看最終成品。
- **同步預覽（`F11`）** — 另開一個**可自由拖曳、縮放**的視窗。程式不去猜要開在哪個
  螢幕（三螢幕環境猜錯反而礙事）：自己拖到想要的那一台，用視窗的最大化鈕、或在畫面上
  **按兩下**切換無邊框全螢幕。
  畫面上**只有照片本身**（調整水平之後保留下來的可視區域，與輸出檔同一個裁切框）－
  沒有格線、黃色裁切框、角度文字、星等、已編輯紅框、進度條，任何主視窗的標示都不會出現。
  這個視窗**沒有任何快捷鍵、也不搶焦點**，所有操作都留在主視窗。
  它**等主視窗算完才動**：連續調角度、連續換張的當下完全不重算，停手約 0.2 秒之後
  才去解碼並畫出完整解析度的畫面 － 主視窗的即時預覽速度完全不受影響。
- **輸出回原始尺寸** — 裁切後再放大回原始像素尺寸（會有一點點放大軟化，預設關閉）。
- **JPEG 品質** — 預設 100。
- **存檔後把原檔移到子資料夾** — 預設開啟，資料夾名稱預設 `ARCHIE`（旁邊的輸入框可改）。
- **快速載入** — 預設開啟。預覽與自動偵測使用縮圖解碼，**存檔一律讀完整解析度**，輸出畫質完全不受影響。
- **切換時自動儲存** — 預設開啟。切到上／下一張前，若目前這張改過角度就先存檔並封存原檔。
- **評分後自動下一張** — 預設開啟。按 `1`~`5` 評完立刻前進，右手不用離開數字鍵區；`0`（清除）與最後一張不前進。搭配「只看未評分」＝按著數字鍵一路把清單清空。
- **效能檢測** — 按一下，在你這台電腦實測 PIL / OpenCV CPU / OpenCL(GPU) 的預覽運算速度，自動挑最快的並記住。

## 效能與硬體加速

### 已經是 64 位元

`Python 3.14.0 win_amd64`，numpy / Pillow / OpenCV 的 wheel 全部都是 `win_amd64` 標籤，
Pillow 帶 **libjpeg-turbo**（SIMD 加速的 JPEG 編解碼）。沒有 32 位元元件混在裡面。
執行 `photo_leveler.py --version` 或按「效能檢測」都會把這些資訊印出來。

### GPU 與 NPU 的實話

- **NPU 幫不上忙**。它是神經網路推論加速器，只吃矩陣乘法。JPEG 解碼、旋轉內插、
  JPEG 編碼一個都碰不到。除非把自動偵測換成 AI 模型 － 但那對這個任務更慢也更不準
  （現在的 LSD 誤差是 0.15°）。
- **GPU 值不值得，取決於「誰在搬資料」**（v1.18 重做）。舊的寫法每一幀都把整張圖
  上傳到 GPU、算完再下載，搬運成本常常把計算省下的時間吃光 － 這就是先前
  「只有邊際效益」的來源。現在預覽的來源影像**常駐 GPU 記憶體**（`cv2.UMat`），
  每一幀只下載算完的結果，GPU 就穩定比 CPU 快了。實測（Intel 內顯 + 14 執行緒 CPU）：

  | 來源尺寸 | PIL | OpenCV CPU | OpenCL 每幀上傳 | **OpenCL 常駐** |
  |---|---|---|---|---|
  | 1600×1067 | 48.5 ms | 4.3 ms | 3.1 ms | **2.5 ms** |
  | 2560×1707 | 125.6 ms | 10.8 ms | 6.6 ms | **6.2 ms** |
  | 3840×2560 | 315.4 ms | 21.9 ms | 21.2 ms | **14.7 ms** |

  預設值因此改成「有 OpenCL 就用 OpenCL，其次 OpenCV CPU」。CUDA 版 OpenCV 仍然
  pip 裝不到，要自己編譯；「效能檢測」按鈕也還在，實測結果會覆蓋預設值。

### 三個實際有效的加速

**1. 背景寫檔** － 存檔（重讀原圖 → 旋轉 → 編碼 → 封存）整包丟給背景執行緒，
介面立刻可以換下一張。6000×4000 存一張約 3.3 秒的等待變成 **0 秒**。

- 輸出**位元完全相同** － 旋轉仍走 `rotate_and_crop()` 的 PIL BICUBIC，改的只有「誰在等」。
- 同一張還在寫入時，再按 `Ctrl+S` 或 `Q` 會被擋下。
- 瀏覽列顯示 `⏳ 背景寫入中 N`，關閉程式時會等寫完才結束。

**2. 預覽運算換 OpenCV** － 只影響螢幕預覽，**完全不碰輸出檔**。

| 運算 | PIL | OpenCV | 加速 |
|---|---|---|---|
| 預覽縮圖 2500×1500 → 1200×800 | LANCZOS 0.067 s | INTER_AREA 0.014 s | 4.7× |
| 預覽旋轉 | BILINEAR | warpAffine | ~3× |

**3. 快速載入**（v1.4.0 已有）－ 縮圖解碼 + LRU 快取 + 背景預先載入。
v1.18 把背景預先載入改成**多執行緒**（`min(4, CPU 執行緒數 / 2)` 條），
快取放大到 10 張、預先載入半徑放大到前後各 3 張。

**4. 每一幀只取樣一次**（v1.18）－ 以前預覽是「旋轉整張 → 裁切 → 縮放」三步，
現在把旋轉、置中裁切、縮到輸出尺寸合併成**單一個仿射矩陣**，一次 `warpAffine` 做完。
少了兩次搬移與一次重複內插，畫面也更銳利一點。Tk 那一端則改成**重用同一個
`PhotoImage`**，只把像素貼進去（`paste`），省下每幀重建 Tk 影像的成本 － 大圖上這幾乎
是一半的時間。合計主視窗預覽從 **約 50 ms／幀降到約 7 ms／幀**。

### 刻意沒有做的事

**輸出的旋轉沒有改成 cv2**。cv2 的 `INTER_CUBIC` 用 a=−0.75 的三次核、PIL 用 a=−0.5，
兩者輸出的 PSNR 差異在 31～40 dB（cv2 稍銳、有輕微 ringing）。速度是快 3.3 倍
（2.15 s → 0.65 s），但這個工具的立場是畫質優先，所以維持 PIL。
背景寫檔已經把「等待」這件事消掉了，速度的需求由那邊滿足。

**JPEG `optimize=True` 沒有關掉**。關掉編碼快 2.3 倍（0.99 s → 0.43 s）、畫質完全相同，
但檔案大 22%（36.6 MB → 44.7 MB）。同樣由背景寫檔解決等待問題。

## 資料夾瀏覽（批次處理）

`Ctrl+Shift+O` 選一個資料夾，程式會列出裡面所有支援的影像檔（**不進子資料夾**），
用**自然排序**排好（`IMG_2` 會排在 `IMG_10` 前面），一次仍然只顯示一張。
用 `Ctrl+O` 開單張檔案時，也會順便把同資料夾的清單建起來，`←` `→` 立刻就能換張。

瀏覽列會顯示 `目前 / 總數` 與資料夾路徑，兩端到底時對應的按鈕會自動變灰。

**預覽區頂端有一條 6px 的進度條** － 暗色底槽 + **琥珀黃**（`#ffb300`）進度，
比例就是「第幾張 / 總數」，與瀏覽列的數字完全一致。實作上是直接畫在 canvas 上的
兩個矩形（tag `progress`），不新增任何 widget、不動版面，所以視窗縮放、切換角度、
忙碌提示都不會影響它。清單為空時（例如貼上的剪貼簿影像）就不畫。

顏色刻意比裁切框的 `#ffd23c` 深一階 － 兩者同時出現在畫面上時仍分得出來
（進度條是頂端的實心橫帶，裁切框是畫面中央的細框線）。
角度資訊與評分大字也一併往下讓出頂端空間。

按 `Q` 淘汰一張時清單會變短，分母跟著變小，所以進度同樣會往前推進。

### 換張的定位機制（v1.16 重寫）

檔案在作業中會改名（`X.jpg` → `X_leveled.jpg`）、會被封存到 `ARCHIE\`、
也可能被篩選條件排除，所以「目前這張」常常已經不在瀏覽清單裡。
換張時用**四層定位**找出應該從哪裡前進／後退，任何一層命中就停：

1. **目前檔案就在清單裡** → 直接命中
2. **同源檔** － 把 `_leveled` / `_mosaic` / `_vN` 後綴**遞迴剝除**後同名的檔案。
   `ARCHIE\X.jpg` 與工作資料夾的 `X_leveled_v2_mosaic.jpg` 剝完都是 `X`，
   所以改名、存檔、上馬賽克之後仍然定位得到原本的位置。
3. **鄰居快取** － 每次顯示照片時記下前後各 5 張與它們的相對位移，
   拿還在清單裡的鄰居往回推算位置。
4. **凍結的排序鍵** － 算出「應該插入的位置」，前一張／下一張各取兩側。

**排序鍵在掃描當下就凍結**，之後不再重算。這點很重要：沒有 EXIF 拍攝日期的
照片是用檔案時間排序，而評分與存檔都會改動 mtime －
若每次都重算，清單順序會在作業途中悄悄變動，往回看時就會看到不同張。

存檔產生的 `_leveled` 成品會**沿用來源的排序鍵**加進清單，
出現在來源原本的位置上，往回看時看到的就是剛才處理的那張。

### 星等篩選（v1.20）

挑選工作流的後半段：先用 `1`~`5` 把整批照片評完，再把星等下拉切到 `★3+`，
清單立刻只剩 3～5 星的照片，`←` `→` 換張自動跳過其他的 － 交件前的複選
不會再看到淘汰品。細節：

- 篩選讀的是檔案裡的 xmp:Rating／EXIF Rating，所以 **XnView MP 評的星一樣能篩**；
  中繼資料有快取（mtime 沒變不重讀），大資料夾切換條件不用重掃。
- 與「只看未評分」**互斥自動切換**：選了星等門檻就自動取消未評分（未評分＝0 星，
  兩者同時成立必是空清單）；反之勾回未評分，星等自動歸「全部」。
- **篩選中改評分會即時生效**：`★3+` 模式下把目前這張改成 2 星（或按 `0` 清除），
  它立刻從清單消失並自動顯示下一張符合的照片。
- 淘汰（-1）在任何星等門檻下都被排除。
- `Ctrl+1`~`Ctrl+5`＝門檻、`Ctrl+0`＝取消，挑片全程不用碰滑鼠；
  門檻存進設定檔，重開程式、換資料夾都自動套用。

### 篩選：只看還沒處理的

瀏覽列有兩個獨立的勾選框，只影響瀏覽清單，不動任何檔案：

| 勾選 | 效果 |
|---|---|
| **只看未調水平** | 隱藏已調過的檔案（檔名含 `_leveled` **或** EXIF 有 PhotoLeveler 標記，雙重偵測） |
| **只看未評分** | 隱藏 `xmp:Rating` ≠ 0 的檔案（有星等或標過淘汰 −1 都算已評） |
| **兩個一起勾** | AND － 只顯示「還沒調水平**而且**還沒評分」的檔案 |

配套行為：

- 計數與進度條都以篩選後的清單為準，顯示「3 / 12（篩選自 200）」。
- 篩選狀態的判斷只讀檔頭（每檔約 0.1~1 ms），結果以 mtime 快取，
  超過 150 個未快取檔案才會出現「篩選中…」提示。
- **剛評完分的那張不會立刻消失**（避免畫面跳動），按 `←` `→` 換張時才重套篩選、
  自動跳到下一張仍符合的檔案 － 「評分 → 下一張」的節奏就是一路把清單清空。
- `Q` 淘汰與篩選相容：檔案移進 `ARCHIE\` 後從兩份清單移除，接著停在下一張符合的。
- 全部處理完（清單空了）會明確告知，取消勾選即可恢復完整瀏覽。
- 篩選狀態不記憶，每次開程式都是關閉的 － 避免「檔案怎麼都不見了」的困惑。

### 切換時自動儲存

預設開啟。切到下一張之前，如果目前這張**改過角度**，會先存成 `_leveled.jpg`
並依封存規則把原檔搬進 `ARCHIE\`，然後才換張。搭配的細節：

- 原檔被封存後會**從瀏覽清單移除**，而且是用「目標檔案路徑」重新定位索引，
  所以清單變短時不會跳錯張。
- 自動儲存**絕不覆蓋原檔**，也不會跳任何對話框打斷批次作業。
- 關掉這個勾選時，切換只會在狀態列補一句「上一張改過但未儲存，已略過」。

### 品質不好，直接淘汰（`Q`）

批次瀏覽時看到不想要的照片，按 `Q` 就把**原檔直接移進 `ARCHIE\`**，
然後自動跳到下一張。這條路徑**不會**產生 `_leveled` 輸出，也不會因為
「切換時自動儲存」而偷偷存檔 － 未儲存的角度直接放棄。

- 移動前會顯示「移到封存中…」提示。
- 封存夾裡已有同名檔案時自動加序號（`C1 (2).jpg`），不覆蓋。
- 按到最後一張、資料夾被清空時不會出錯，畫面會清乾淨並說明。
- 剪貼簿貼上的圖沒有原檔可搬，按 `Q` 只會在狀態列提示。
- 已經在封存夾裡的檔案再按 `Q` 會被擋下，不會愈疊愈深。

**`Ctrl+Z` 可以還原最近一次的 `Q`** － 檔案搬回原位、重新掃描資料夾並停在那一張。
只記最近一次，而且只涵蓋 `Q` 這個動作（存檔造成的封存不在還原範圍內）。
因為檔案只是被移動、沒有刪除，即使超出還原範圍也隨時能自己從 `ARCHIE\` 搬回來。

### 已調整過水平的檔案（雙重偵測）

判斷一張照片有沒有被這個工具處理過，用**兩個獨立訊號**，任一命中就算：

**1. 檔名** － 檔名（不含副檔名）**任何位置**出現 `_leveled`，不分大小寫。

| 檔名 | 判定 | 下一次的輸出 |
|---|---|---|
| `IMG_001.jpg` | 未調整 | `IMG_001_leveled.jpg` |
| `IMG_001_leveled.jpg` | **已調整** | `IMG_001_leveled_v2.jpg` |
| `IMG_001_LEVELED.JPG` | **已調整** | `IMG_001_LEVELED_v2.jpg` |
| `IMG_001_leveled_v10.jpg` | **已調整** | `IMG_001_leveled_v11.jpg` |
| `IMG_001_leveled_x.jpg` | **已調整** | `IMG_001_leveled_x_v2.jpg` |
| `my_leveled_photo.jpg` | **已調整** | `my_leveled_photo_v2.jpg` |
| `IMG_001_leveled 副本.jpg` | **已調整** | `IMG_001_leveled 副本_v2.jpg` |
| `leveled.jpg` | 未調整（沒有底線） | `leveled_leveled.jpg` |
| `IMG_001_final.jpg` | 未調整 | `IMG_001_final_leveled.jpg` |

版次規則：檔名結尾是 `_v<數字>` 就把號碼加一，否則直接接 `_v2`；
遇到已存在的號碼會往後找，不會蓋掉既有版本。

**2. EXIF 標記** － 每次存檔都會在 **EXIF 的 `Software` 欄位**寫入：

```
PhotoLeveler 1.8.0 leveled +1.75deg
```

只覆寫 `Software`，相機廠牌、型號、拍攝時間、ICC 描述檔等原有欄位都完整保留。
這個標記**跟著檔案走** － 改名、複製到別台電腦、丟進其他資料夾都還認得出來，
而且順便記錄了上次轉了幾度。

讀取成本只有 **0.08 ms**（只讀檔頭不解碼），而且是在載入時順手解出來的，
不會為了判斷而多開一次檔。

**紅框的範圍是「所有編輯過的檔案」**（v1.12 起）：調過水平（`_leveled`／EXIF
`leveled` 標記）**或**上過馬賽克（`_mosaic`／EXIF `mosaic` 標記）都會顯示粗紅框
與瀏覽列提示，存檔時**不封存原檔**（歷代版本都留在工作資料夾方便比較）。
馬賽克輸出的 EXIF 標記會保留 leveled 資訊再補上 mosaic
（例：`PhotoLeveler 1.9.0 leveled +1.75deg +mosaic`），所以改名也分得出兩種編輯。
「只看未調水平」篩選看的仍然是**水平**訊號 － 只上過馬賽克的檔案不會被它藏起來。

> 注意：角度為 0 時走的是**原檔無損複製**，不重新編碼，所以不會蓋 EXIF 標記 －
> 那種情況本來就沒有真的調整過水平。

## 星等評分（給 XnView MP 用）

一邊調水平一邊挑照片。按 `1`~`5` 給星、`0` 清除、`-` 或 `Q` 淘汰。
瀏覽列與預覽右上角都會顯示目前星等。

### 人臉模型的尋找方式（v1.13 強化）

**模型檔已直接放在本資料夾**（`face_detection_yunet_2023mar.onnx`），
`MosaicTool` 資料夾之後棄用也不影響。搜尋順序：設定檔指定 → PyInstaller 內嵌 →
程式所在資料夾往上最多三層、每層順便找 `MosaicTool` 子資料夾。
真的找不到時，按「偵測人臉」會開檔案視窗讓你指定 onnx 一次，之後記住。

**打包**：`build_exe.bat` 會把模型用 `--add-data` 內嵌進 exe
（模型不在時打包會直接報錯，不會做出殘缺的 exe），
執行期由 `_MEIPASS` 讀取 － 打包後的 exe 單檔即可完整使用馬賽克功能。

**版本**：`2023mar` 是 OpenCV 官方模型庫（opencv_zoo）目前**最新**的 YuNet
浮點模型 － 官方只另有 int8 量化變體，沒有更新的版本。
檔案大小 232,589 bytes 與官方一致。

### 圖片上的大字評分（v1.12）

評分不再只是角落小字 － 預覽右上角直接壓上**大號數字**（34pt 粗體）＋星星列
＋半透明底框：`4` 金黃色、淘汰顯示紅色 `✕`，未評分不顯示。一眼就知道這張評過沒。

### 寫哪些欄位

三個一起寫，涵蓋常見軟體，你不用去設定任何一邊：

| 欄位 | 位置 | 誰會讀 |
|---|---|---|
| `xmp:Rating`（−1～5） | XMP 封包（APP1） | **XnView MP**、Adobe Bridge、Lightroom、digiKam、FastRawViewer |
| `MicrosoftPhoto:Rating`（0/1/25/50/75/99） | XMP 封包 | Windows 檔案總管 |
| EXIF `Rating` (0x4746) + `RatingPercent` (0x4749) | EXIF IFD0 | Windows 檔案總管、XnView MP |

`-1` 是 XMP 標準裡的 **rejected**（淘汰）。EXIF 沒有負值，所以評分 ≤ 0 時
會把 EXIF 的兩個評分欄位清掉，只留 XMP 的 −1。

### 評分是無損的

評分屬於中繼資料，**不該為了改它而重新編碼照片**。所以寫入走的是 JPEG 區段層級的
改寫：只替換 APP1（EXIF / XMP）區段，`SOS` 之後的壓縮資料一個位元組都不碰，
再用暫存檔 + `os.replace()` 原子性換掉原檔。

實測（1200×800、連續改 6 次評分）：**像素雜湊完全相同**，相機廠牌／型號／拍攝時間
全部保留，既有的 XMP 欄位（例如 Lightroom 寫的 `dc:creator`）也不會被吃掉，
而且不會產生重複的 `xmp:Rating`。

### 寫到哪裡

- **立即寫進目前這張原檔** － 按下數字鍵就寫好了，就算這張不調水平也留得住評分。
- **存檔時一併帶進 `_leveled` 輸出** － 處理後的檔案同樣有評分。
- 非 JPEG（PNG / TIFF 等）無法就地改寫，評分會留在記憶體、存檔時寫進輸出檔，
  狀態列會說明。
- 剪貼簿貼上的影像沒有原檔，同樣是存檔時才寫入。

### 與淘汰的整合

`Q` 和 `-` 是同一個動作：**先蓋上 `xmp:Rating = -1`，再把原檔移進 `ARCHIE\`**，
然後跳下一張。之後在 XnView MP 裡看封存資料夾，一眼就分得出哪些是主動淘汰的。
`Ctrl+Z` 一樣可以還原。

## 馬賽克（整合自 MosaicTool）

按 **`M`**（或工具列「馬賽克」按鈕）對**目前正在看的這張**開馬賽克視窗 －
效果核心（YuNet 人臉偵測、柔焦／半調／混合／純色塊、羽化邊緣）從
`T:\plug-ins\MosaicTool` 原封不動移植，介面改為同程式內的 tkinter 視窗，
**預設不載入**：人臉模型在第一次按「偵測人臉」時才讀取，平常零啟動成本。
模型檔會自動尋找：本資料夾 → 隔壁 `MosaicTool\` 資料夾。

### 操作

| 動作 | 方式 |
|---|---|
| 新增框 | 在預覽上拖曳 |
| 刪除框 | 右鍵點框 |
| 自動框人臉 | **開窗即自動偵測**；「偵測人臉」按鈕可再補跑 |
| **人臉外擴** | 偵測到的人臉框自動往外擴 **15%**（預設，每邊各擴），滑桿 0~50% **即時調整**；手動框不受影響 |
| 效果 | 柔焦／半調／混合（預設）／純色塊，三個滑桿即時預覽 |
| **視窗縮放** | 直接拖曳視窗邊框或最大化，圖片**自動等比滿版並置中**（見下） |
| 完成 | 「儲存並封存原檔」 |

完整的進階參數與原版一致：**效果模式**（柔焦／半調／混合／純色塊）、
**點陣形狀**（方形／圓形／鑽石）、**點陣粒度**、**柔焦強度**、**混合比例**、
**邊框柔焦**、**外框羽化**，滑桿標籤即時顯示數值。
預設值直接讀你的 `MosaicTool\dist\MosaicTool.ini`，之後在這裡調過就記住。
人臉框顯示綠色、手動框紅色，與原版一致。

### 視窗縮放：圖片自動滿版（v1.17）

馬賽克視窗可以自由拉大、拉小、最大化，圖片會**等比縮放到滿版**並置中，
不會變形、不會被裁掉。小圖也會放大（上限 4×，避免預覽吃掉記憶體）。

實作上有三個重點：

- **框永遠存全解析度座標**。畫面上的框是 `全解析度座標 × 目前縮放比` 畫出來的，
  所以縮放視窗不會動到任何一個框，儲存出來的結果跟你在哪個視窗大小下框的無關。
- **滑鼠座標反算含置中位移**。圖片置中時左右（或上下）會留邊，
  拖曳新增框與右鍵刪除框都會先扣掉這個位移再除以縮放比，落點才不會偏。
- **120ms 防抖**。拖曳視窗邊框會連續丟出幾十個 `<Configure>` 事件，
  每個都重算一次縮圖會卡住；改成延遲合併，且尺寸變化 ≤2px 時直接跳過不重算。
  縮小用 `INTER_AREA`、放大用 `INTER_LINEAR`。

視窗有最小尺寸 720×480，再小右側控制面板會被擠掉。

### 單張模式（`Shift+M`）

處理跟目前瀏覽無關的單張照片時用這個。按 `Shift+M` 開「選擇來源」小窗，
三種方式都可以：**把檔案拖進去**、**`Ctrl+V` 貼上剪貼簿**（圖片或複製的檔案）、
或按「開啟檔案…」。

與一般模式的差別：

| | 一般（`M`） | 單張（`Shift+M`） |
|---|---|---|
| 對象 | 目前瀏覽中的照片 | 任一張（拖放／貼上／開檔） |
| 輸出 | 原檔名 + `_mosaic` | 同左；剪貼簿影像會問你存哪裡 |
| 原檔 | 依規則封存進 `ARCHIE\` | **不封存，原地不動** |
| 瀏覽清單 | 同步更新、跳下一張 | **完全不動** |

### 與挑選工作流的整合

- **角度改過還沒存 → 自動先存**：走既有存檔流程（產生 `_leveled`、封存原檔），
  再對新的 `_leveled` 檔上馬賽克。評分是即時寫入的，本來就不需要等。
- **後綴完整保留**：輸出在**同一層工作資料夾**，
  `IMG_001_leveled.jpg → IMG_001_leveled_mosaic.jpg` － `_leveled` 與 `_mosaic`
  都在，篩選照常認得（含 `_leveled` 的馬賽克檔會被「只看未調水平」正確隱藏）。
- **來源檔照封存邏輯移進 `ARCHIE\`**，工作資料夾只留最新成品；
  瀏覽清單同步（來源移除、成品加入），存完自動跳到下一張。
- **中繼資料完整帶過去**：原版 MosaicTool 用 cv2 存檔會把 EXIF/XMP 全部丟掉，
  移植版改用與主程式相同的存檔路徑 － **星等評分、PhotoLeveler 標記、
  相機資訊、ICC 全部跟著 `_mosaic` 檔走**，XnView 照樣篩得到。

> `MosaicTool` 資料夾本身完全沒有被修改，單獨雙擊 `MosaicTool.exe` 的行為不變。

## 除塵（CMOS 感應器入塵修補）

相機感光元件入塵時，照片上會出現**暗色、邊緣模糊的小圓斑**（光圈越小越明顯），
固定出現在畫面同一位置，天空這種平滑區最礙眼。按 **`B`** 開啟除塵視窗
（與馬賽克同一套操作模式的獨立編輯視窗）：

### 操作

- **綠圈＝自動偵測**：開窗即自動掃描。只抓「平滑區、離任何結構夠遠、背景夠亮」
  的暗斑 － 機身、建築等物體表面**絕不自動圈選**，不會誤傷真實細節。
- **紅圈＝手動點選**：左鍵點一下＝以「手動點半徑」新增；**左鍵拖曳＝拖多遠圈多大**；
  右鍵點圈＝刪除（自動、手動都可刪）。機身上的塵斑請手動點，存檔前看預覽確認。
- **偵測靈敏度**＋**斑徑上限**兩個滑桿一起控制偵測，拖動即時重新掃描：
  靈敏度對應「斑至少要比背景暗幾階」（高 ISO 時自動改用雜訊門檻，不會滿天誤判）；
  斑徑上限決定「多大的暗塊還算塵斑」（它就是背景估計的中值濾波核）。
- **沿用上次的點（v1.22 強化）**：入塵黏在感應器上，同一批照片的斑點位置都相同，
  所以每次除塵存檔就把點位**寫進設定檔** － 換照片、換資料夾、**重開程式**都還在。
  每張 `_leveled` 檔的裁切尺寸差幾個像素也沒關係：長寬比一致（2% 內）就
  **自動等比換算**（按鈕會顯示「自動縮放」）；只有方向不同（直幅 vs 橫幅）
  或比例差太多才會停用。沿用進來是紅圈，照樣可以增刪微調。
- **不會累加（v1.22.1）**：沿用時只補「這張還沒有」的位置 － 自動偵測（綠圈）
  已涵蓋的同一顆塵斑直接略過；沿用後再「重新偵測」也不會疊圈；
  存檔前重疊的點會先合併再寫進設定檔。連按幾次沿用、處理多少張，
  點數都維持在「實際塵斑數」，不會一代一代雪球式增加。
- 預覽即時顯示修補結果；存檔輸出 `原檔名_clean.jpg` 並依既有邏輯封存原檔，
  EXIF 蓋 `+clean` 標記（紅框、篩選、同源判定都認得）。
- **同步預覽連動（v1.21）**：同步預覽開著（或在編輯視窗裡按 `F11` 開啟）時，
  全螢幕畫面即時顯示**編輯後的結果** － **馬賽克與除塵視窗都支援**，
  依同步視窗自己的解析度重算效果，不是把小預覽放大；每加減一個框點、
  調一次滑桿都跟著更新（除塵的「預覽修補結果」關掉時顯示原圖）。
  關閉編輯視窗自動交還畫面。

### 原理與品質保證

- **偵測（v1.24 響應圖重做，靈敏度約 4 倍）**：中值濾波估「沒有斑的背景」後，
  不再用「背景 − 原圖」的絕對差，改走三段前處理：
  ① **輕度去噪**（σ1.2 高斯）先壓感光雜訊；
  ② **透射率正規化**（flat-field 除法，天文／顯微鏡標準作法）－ 塵斑是
  **乘法性遮光**，同一顆塵在亮背景的絕對凹陷大、暗背景小，改算「相對吸收率」
  之後暗一點的天空一樣抓得到，靈敏度滑桿的單位也變成物理量（遮掉幾 % 的光）；
  ③ **多尺度高斯平滑取最大**（圓斑匹配濾波）－ 把整顆斑的能量聚起來，
  單像素雜訊聚不起來，極淡的斑就浮出雜訊面。
  雜訊門檻用平滑區響應的「中位數＋3×MAD」估計（不被地面結構污染）；
  銳利度改在去噪影像上量（軟塵 ≤1.5、鳥／實體 ≥2.6，高 ISO 雜訊不會灌高邊緣值）。
  排除實體的邏輯（v1.23 重做）是**分級制**：
  「邊緣銳利度／斑深」比值 ≤2.2 一定是失焦柔斑、>4.0 一定是實體（鳥、電線），
  中間地帶用**圓形度**裁決 － 入塵斑光學上接近圓形，夠圓就是塵。
  一刀切在 2.0 的舊版會專殺「顏色最深、最明顯」的斑（斑越深、邊緣梯度按比例越陡）。
  另外加了**細紋理防護**：斑點周圍一圈的局部標準差太高（柏油路面、草地的顆粒）
  就略過 － 塵斑是高亮度平滑背景下才顯影的干擾，有紋理的地方本來就看不見；
  門檻隨全圖雜訊自適應，高 ISO 不會整張被排除。背景亮度 <90 的暗部同樣略過。
- **修補**：逐斑取小塊 ROI 做 `cv2.inpaint`（Telea，與 Lightroom 汙點移除同原理），
  用周圍像素重建。ROI 裡的**強邊緣會先從遮罩扣掉**，斑貼著機身輪廓時
  兩側各修各的，輪廓完全保留。
- **斑點以外的像素 100% 位元不變** － 實測 3444×1939 全圖修 11 個斑，
  被改動的像素只佔全圖 0.03%。
- 實測合成資料：塵斑找回 14/14、6 隻鳥 0 誤判；真實照片（RCTP 停機坪）
  預設靈敏度自動抓到 11 個斑，全部正確、天空修補後無痕。

## 存檔後自動封存原檔

存檔成功後，原始檔案會被搬到**它自己所在目錄底下**的 `ARCHIE\` 子資料夾，
工作資料夾就只留下調整後的 `_leveled.jpg`。旁邊的「開啟封存資料夾」按鈕可以直接叫出檔案總管。

搬移只在**全部條件成立**時才發生，任何一項不符就整個跳過，原檔原地不動：

| 條件 | 原因 |
|---|---|
| 勾選框有開 | 你隨時可以關掉，設定會記住 |
| 有原始檔案 | 從剪貼簿貼進來的圖沒有原檔可搬 |
| 角度不為 0 | 沒真的調整過就不算「處理完」，原檔留在工作資料夾 |
| 輸出路徑 ≠ 原檔路徑 | 你選擇覆蓋原檔時，搬走會讓檔案整個消失 |
| 原檔還不在封存夾裡 | 避免同一張重複搬、或把封存夾愈疊愈深 |

其他細節：

- **同名不覆蓋** — 封存夾裡已有同名檔案時，自動變成 `照片 (2).jpg`、`照片 (3).jpg`。
- **封存後再存一次仍然正常** — 程式記著「工作資料夾」的位置（`origin_dir`），
  所以第二次 `Ctrl+S` 的輸出還是落在工作資料夾，不會跑進封存夾裡。
- **資料夾名稱會清理** — 輸入 `< > : " / \ | ? *` 這些 Windows 不允許的字元會自動去掉，
  清完變空字串就退回預設的 `ARCHIE`。
- **搬移失敗不影響存檔** — 檔案被其他程式鎖住之類的情況，狀態列會顯示原因，
  但調整後的檔案已經先存好了。

## 技術細節

### 拖放與剪貼簿

拖放用 **Windows 原生 `WM_DROPFILES`** 實作：以 ctypes 取得視窗 HWND，
呼叫 `DragAcceptFiles` 後把視窗程序（WndProc）接管起來，收到 `WM_DROPFILES`
就用 `DragQueryFileW` 取出檔案清單，再排進 Tk 的事件佇列處理。
**不需要 tkinterdnd2 之類的第三方套件**，所以不必重建 `.venv`，
在非 Windows 或任何初始化失敗的情況下會靜默停用，不影響其他功能。

貼上用 `PIL.ImageGrab.grabclipboard()`，同時處理兩種回傳型態
（影像物件／檔案路徑清單），再退一步嘗試把剪貼簿純文字當成路徑。
複製出去用 Windows 剪貼簿的 **`CF_DIB`** 格式：把影像存成 BMP 後去掉前 14 bytes 的
`BITMAPFILEHEADER`，剩下的 `BITMAPINFOHEADER` + 像素資料放進 `GlobalAlloc` 的
可移動記憶體交給系統。

### 快速載入

三層機制，實測從 6000×4000 的 JPEG 換到下一張，端到端快 **2.3～3.7 倍**：

1. **縮圖解碼（PIL `draft`）** — JPEG 的 DCT 結構允許 libjpeg 直接以 1/2、1/4、1/8
   解碼，省掉大部分反量化與 IDCT。要求值必須**維持原始長寬比**，因為 `draft` 的規則是
   「結果不得小於要求尺寸」－ 對 6000×4000 要求 `(2000, 2000)` 會因為短邊過不了關而
   整個不縮，要求 `(1400, 933)` 才會真的降到 1/4。目標長邊設 **1400px**，
   刻意與自動偵測的取樣解析度一致。
2. **LRU 快取** － 最近 6 張解碼結果留在記憶體，往回翻是即時的。
3. **背景預先載入** － 一條 daemon 執行緒把前後各 2 張先解碼進快取。
   該執行緒只碰 PIL 與快取、完全不碰 Tk，所以沒有執行緒安全問題。

**畫質保證**：`self.image` 只用於預覽與偵測，輸出走 `_full_image()` 重讀完整解析度，
顯示的輸出尺寸也一律以 `full_size`（含 EXIF 方向修正後的原始尺寸）計算，
與縮圖無關。介面上的「快速載入」可隨時關閉，關閉時會清空快取並重讀目前這張。

實測比較（同樣的 7 個已知角度）：完整解碼最大誤差 0.00°、快速解碼最大誤差 **0.15°**，
遠低於 0.35° 的既有標準 － 因為偵測本來就會把影像縮到 1400px。

| 原始尺寸 | 完整流程 | 快速流程 | 加速 |
|---|---|---|---|
| 8000×6000 | 1.054 s | 0.292 s | 3.6× |
| 6000×4000 | 0.536 s | 0.145 s | 3.7× |
| 4000×3000 | 0.291 s | 0.126 s | 2.3× |
| 3000×2000 | 0.151 s | 0.062 s | 2.4× |

### 自動偵測水平

主要使用 **OpenCV LSD（Line Segment Detector）**，若目前的 OpenCV 版本不提供
（LSD 曾在 4.1–4.7 因專利被移除），會自動退回 **`ximgproc.FastLineDetector`**，
再退回 **Canny + HoughLinesP**。狀態列會顯示實際使用哪一種。

流程：

1. 縮到長邊 1400px 做偵測（速度與穩定度的平衡）。
2. 取出所有線段，濾掉太短的。
3. 把「接近水平」（±12°）和「接近垂直」（±12°，減 90° 換算）的線段一起收集。
4. 以線段長度為權重做**核密度投票**（σ=0.5°）找主峰 — 比取平均或中位數穩定得多，
   不會被少數斜線帶偏。
5. 在主峰 ±1° 內做加權平均精修，得到最終角度。

偵測是**手動觸發**的 － 按 `D`（或 `A`、或工具列按鈕）才會執行，開檔、換張、拖放、貼上都不會自動偵測。
執行後角度會**直接套用**到預覽（`set_angle()`），並標記成未儲存；按 `R` 可以歸零重來。
「不會自動」指的是**不會自動存檔**，不是不套用角度。
`偵測依據` 下拉可以選「水平＋垂直線 / 只看水平線 / 只看垂直線」——
拍建築、室內、產品照時，選「只看垂直線」常常更準。

### 同步預覽（v1.18）

- **開在哪裡**：就是一個普通的 `Toplevel`，開在主視窗旁邊、預設 960×640，可拖可縮。
  **不做螢幕偵測** － 多螢幕環境下猜錯比不猜還糟。按兩下時才用 `MonitorFromWindow` +
  `GetMonitorInfo` 問「這個視窗現在在哪個螢幕」，`overrideredirect(True)` + 指定該螢幕
  的矩形做無邊框全螢幕（Tk 自己的 `-fullscreen` 會把視窗拉回主螢幕，不能用）。
- **畫什麼**：只有 `PreviewSource.render(angle, crop=True)` 的結果 －
  與輸出檔用同一個 `inscribed_scale()` 裁切框。所有主視窗的 canvas 標示都不在這裡畫。
- **等主視窗算完才動**：主視窗每次重畫只是把防抖計時器往後推，連續調整期間這裡
  一次都不重算；停手 180 ms 之後才動，而且一律用品質最好的 `INTER_CUBIC`。
  實測 32 步的角度掃描：同步視窗重畫 **0 次**，停手後 **1 次**。
- **解析度**：來源影像會依視窗大小重縮一份，尺寸取「裁切後仍足以鋪滿視窗」的大小，
  避免先縮小再放大。可視比例 `k` 以 0.05 為一段做分段，並保留最近三種尺寸的來源，
  回頭調同一段的角度時不用重做縮圖。
- **快速載入時的畫質**：預覽影像是 1400 px 的縮圖，對大螢幕不夠用，所以**停手之後**
  才用背景執行緒把原檔完整解碼一份。而且**連縮圖也在背景做完** － 背景交回來的
  已經是「同步預覽正好要的尺寸」的 ndarray（例如 3440×1440 全螢幕就是 2160×1440），
  主執行緒從頭到尾不必碰 6000×4000 的原圖。結果經 `queue` 交回，不跨執行緒碰 Tk。
- **換張直接中斷**：每次換張把 `_fs_token` 加一，背景解碼在各階段之間檢查這個號碼，
  發現換過了就丟 `LoadCancelled` 收工；已經解完的結果也會因為號碼不符而作廢。
  libjpeg 的那一次解碼呼叫本身無法中途打斷，但因為解碼是「停手才開始」，
  快速連續換張時它根本還沒起跑。
- **主視窗永遠優先**：換下一張絕對不受同步預覽影響，靠四件事一起保證 －
  ①「停手才動」的防抖，每次重畫都把計時器往後推；
  ② 計時器到期時若主視窗還在忙（`_busy_on`）或還有排隊中的重畫，就再等一輪；
  ③ 背景解碼執行緒降到 `THREAD_PRIORITY_BELOW_NORMAL`，不跟介面搶 CPU；
  ④ 貴的工作（解碼 + 縮圖）全在背景，主執行緒只剩 GPU 旋轉與貼圖。

  實測 6 張 6000×4000、同步預覽在 3440×1440 全螢幕：

  | 情境 | 每次換張（中位數） | 最慢 |
  |---|---|---|
  | 沒開同步預覽 | 46 ms | 180 ms |
  | 同步預覽全螢幕、連按下一張 | 42 ms | 64 ms |
  | 同步預覽全螢幕、每張停 300 ms | 40 ms | 46 ms |

  同步預覽自己那一次重畫（主執行緒）約 42 ms：建立來源含 GPU 上傳 1.7 ms、
  `warpAffine` 雙三次 22.7 ms、Tk 貼圖 17 ms。改版前光是把原圖轉成 ndarray 再縮
  就要 65 ms，現在那 65 ms 完全移到背景。
- **不干擾操作**：視窗沒有綁任何按鍵，開啟與切全螢幕之後都會把焦點還給主視窗，
  所以 `Z X C V`、`←` `→`、`1`~`5` 這些鍵一律由主視窗接手。

### 裁切數學

旋轉後要找「與原圖同長寬比、置中、完全落在有效像素內」的最大矩形。
設縮放係數 k、半寬 W=kw/2、半高 H=kh/2，把四角轉回原圖座標後必須滿足
`|x| ≤ w/2` 且 `|y| ≤ h/2`，展開得到：

```
k ≤ (w − 2m) / (w·cosθ + h·sinθ)
k ≤ (h − 2m) / (w·sinθ + h·cosθ)
```

取兩者較小值。`m = 1px` 是安全邊，避免雙三次內插在邊界取樣到空白而出現黑邊。

輸出尺寸還會把原始長寬比**約分**（例如 3:2、4:3、16:9）後取整數倍，
所以輸出比例與原圖是**完全相同**，不是四捨五入後的近似值。

### 輸出品質

- JPEG **quality 100**、**subsampling 0（4:4:4）** — 不做色度抽樣，色彩邊緣不會劣化。
- 保留原檔的 **EXIF** 與 **ICC 色彩描述檔**。
- 開檔時先套用 EXIF Orientation 轉正，避免二次旋轉。
- 旋轉用 **BICUBIC** 內插；勾選「輸出回原始尺寸」時放大用 **LANCZOS**。
- **角度為 0 時直接複製原檔**（不重新編碼），完全無損。

實測重新編碼後 PSNR 約 50 dB，視覺上無損。
